# Meeting Rooms with Minimum Gap

## 1. Problem Statement

We are given a 2D array `meetings`, where each meeting is represented as `[start, end]`.

We are also given an integer `g`, which represents the minimum gap required between two meetings scheduled in the same room.

Our task is to find the **minimum number of meeting rooms required to accommodate all meetings**.

### Conditions

- Each meeting has a start time and an end time.
- Two meetings cannot overlap in the same room.
- At least `g` minutes must be available between consecutive meetings in the same room.
- A room can be reused if the previous meeting's end time plus the required gap is less than or equal to the next meeting's start time.

### Example

**Input:**

```java
meetings = new int[][] {
    {10, 30},
    {35, 50},
    {20, 40}
};

g = 5;
```

**Output:**

```text
2
```

### Explanation

We have three meetings:

- Meeting 1: `[10, 30]`
- Meeting 2: `[35, 50]`
- Meeting 3: `[20, 40]`

The minimum required gap between meetings is `5` minutes.

We can schedule the meetings as follows:

| Room | Meeting Schedule |
|---|---|
| Room 1 | `[10, 30]` → `[35, 50]` |
| Room 2 | `[20, 40]` |

The first meeting ends at time `30`. The next meeting in Room 1 starts at time `35`.

Since `30 + 5 = 35`, the required gap is satisfied exactly.

However, the meeting `[20, 40]` overlaps with the first meeting, so it must be assigned to another room.

Therefore, the **minimum number of rooms required is 2**.

---

## 2. Approach 1: Brute Force

### Intuition

The brute-force approach tries to assign every meeting to an existing room.

We maintain a list containing the ending time of the last meeting assigned to each room.

For every meeting:

1. Check the rooms one by one.
2. If a room's previous meeting ends at time `previousEnd`, check whether `start >= previousEnd + g`.
3. If the condition is satisfied, reuse that room and update its ending time.
4. Otherwise, continue checking the remaining rooms.
5. If no room is available, create a new room.

### Java Code

```java
import java.util.*;

class Solution {
    public int minRooms(int[][] meetings, int g) {

        // Sort meetings by their start times.
        Arrays.sort(meetings,
                (a, b) -> Integer.compare(a[0], b[0]));

        // Stores the ending time of the last meeting
        // assigned to each room.
        List<Integer> rooms = new ArrayList<>();

        for (int[] meeting : meetings) {

            int start = meeting[0];
            int end = meeting[1];

            boolean assigned = false;

            // Check every existing room.
            for (int i = 0; i < rooms.size(); i++) {

                // Check whether the required gap is available.
                if (start >= rooms.get(i) + g) {

                    // Reuse this room.
                    rooms.set(i, end);

                    assigned = true;
                    break;
                }
            }

            // If no existing room is available,
            // create a new room.
            if (!assigned) {
                rooms.add(end);
            }
        }

        return rooms.size();
    }
}
```

### Complexity Analysis

- **Time Complexity:** `O(n²)` in the worst case for assigning meetings to rooms, plus `O(n log n)` for sorting.
- **Overall Time Complexity:** `O(n²)`.
- **Space Complexity:** `O(n)` for storing room ending times, excluding sorting overhead.

### Limitation

For a large number of meetings, checking every room for every meeting is inefficient.

We can improve this using a min-heap.

## 3. Approach 2: Optimal Approach Using a Min-Heap

### Intuition

Instead of checking every room one by one, we use a **min-heap (PriorityQueue)**.

A min-heap allows us to efficiently access the room that becomes available earliest.

For each meeting, we store:

`meetingEnd + g`

This represents the earliest time at which the room can be reused.

### Algorithm

1. Sort the meetings by their start times.
2. Create a min-heap to store the earliest reusable time for each occupied room.
3. Process meetings in ascending order of start time.
4. Before assigning a meeting, remove all heap entries whose reusable time is less than or equal to the current meeting's start time.
5. Add the current meeting's ending time plus `g` to the heap.
6. After processing all meetings, the heap size represents the number of rooms required by this greedy scheduling process.

### Java Code

```java
import java.util.*;

class Solution {
    public int minRooms(int[][] meetings, int g) {

        // Step 1: Sort meetings by start time.
        Arrays.sort(meetings,
                Comparator.comparingInt(a -> a[0]));

        // Step 2: Store each room's earliest reusable time.
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        for (int[] meeting : meetings) {

            int start = meeting[0];
            int end = meeting[1];

            // Step 3: Release rooms whose required gap is complete.
            while (!minHeap.isEmpty()
                    && minHeap.peek() <= start) {

                minHeap.poll();
            }

            // Step 4: Assign the current meeting to a room.
            // The room becomes reusable at end + g.
            minHeap.offer(end + g);
        }

        // Step 5: Return the number of rooms required.
        return minHeap.size();
    }
}
```

**Important:** This implementation uses the standard greedy min-heap technique. It assumes meetings are processed in ascending order of start time.

### Why Does the Min-Heap Help?

A min-heap keeps the smallest reusable time at its root.

For example:

```text
Min-Heap: [35, 45]
```

The earliest reusable time is `35`.

If the next meeting starts at `35`, we can reuse that room because the required gap has been satisfied.

We remove the available room's entry and insert the new meeting's reusable time.

This avoids scanning every room individually.

## 4. Dry Run of the Optimal Approach

### Input

```java
meetings = [[10, 30], [20, 40], [35, 50]]
g = 5
```

The input is already sorted by start time.

We store `end + g` in the min-heap.

### Initial State

```text
Min-Heap = []
```

### Iteration 1: Meeting `[10, 30]`

- Start time = `10`
- End time = `30`
- The heap is empty.
- No room is available to reuse, so we allocate a room.
- Insert `30 + 5 = 35`.

```text
Min-Heap = [35]
Rooms required = 1
```

### Iteration 2: Meeting `[20, 40]`

- Start time = `20`
- End time = `40`
- The earliest reusable time is `35`.
- Since `35 > 20`, the first room is not available.
- Allocate another room.
- Insert `40 + 5 = 45`.

```text
Min-Heap = [35, 45]
Rooms required = 2
```

### Iteration 3: Meeting `[35, 50]`

- Start time = `35`
- End time = `50`
- The earliest reusable time is `35`.
- Since `35 <= 35`, one room is available.
- Remove `35` from the heap.
- Insert `50 + 5 = 55`.

```text
Min-Heap = [45, 55]
Rooms required = 2
```

### Final Output

```text
2
```

The answer is **2 meeting rooms**.

### Dry-Run Summary

| Meeting | Start | End | Heap Before Processing | Action | Heap After Processing |
|---|---:|---:|---|---|---|
| `[10, 30]` | 10 | 30 | `[]` | Allocate a room | `[35]` |
| `[20, 40]` | 20 | 40 | `[35]` | Allocate another room | `[35, 45]` |
| `[35, 50]` | 35 | 50 | `[35, 45]` | Reuse an available room | `[45, 55]` |

## 5. Time and Space Complexity

### Sorting

```java
Arrays.sort(meetings, Comparator.comparingInt(a -> a[0]));
```

- Time Complexity: `O(n log n)`
- Space Complexity: Depends on the sorting implementation.

For Java's object-array sorting, auxiliary space can be `O(n)` in the worst case.

### Min-Heap Operations

For each meeting:

- Inserting an element into the heap takes `O(log n)` in the worst case.
- Removing an element takes `O(log n)` in the worst case.
- Each meeting's heap entry is inserted once and removed at most once.

Therefore, all heap operations take `O(n log n)` in the worst case.

### Overall Complexity

Sorting:

`O(n log n)`

Heap processing:

`O(n log n)`

Total:

```text
O(n log n) + O(n log n)
= O(2n log n)
= O(n log n)
```

We drop constant factors such as `2` in Big-O notation.

**Final Complexity:**

- **Time Complexity:** `O(n log n)`
- **Space Complexity:** `O(n)`

### What If the Input Is Already Sorted?

If the meetings are already sorted by their start times, we can remove the sorting statement.

```java
// No sorting required if the input is already sorted.
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
```

The heap processing still takes `O(n log n)` in the worst case.

Therefore, the overall time complexity remains `O(n log n)`.

## 6. Understanding the Java Sorting Method

We discussed the following sorting statement:

```java
Arrays.sort(meetings, Comparator.comparingInt(a -> a[0]));
```

### What Is It Called?

It is **sorting using a Comparator and a lambda expression**.

### Explanation

**`Arrays.sort()`**

This is a Java method from the `Arrays` utility class used to sort arrays.

**`Comparator.comparingInt()`**

This creates a comparator based on an integer value extracted from each array element.

**`a -> a[0]`**

This lambda expression selects the first element of each meeting interval, which represents the start time.

Therefore, the meetings are sorted in ascending order of their start times.

### Example

Before sorting:

```text
[[10, 30], [35, 50], [20, 40]]
```

After sorting:

```text
[[10, 30], [20, 40], [35, 50]]
```

### Alternative Syntax

The same sorting logic can be written as:

```java
Arrays.sort(meetings,
        (a, b) -> Integer.compare(a[0], b[0]));
```

Both statements sort the meetings by start time in ascending order.

## 7. Follow-Up: How Do Time Complexities Combine?

We discussed whether `O(n)` and `O(log n)` should be added or multiplied.

### Case 1: Sequential Operations

If one operation takes `O(n)` and another takes `O(log n)`, the total is:

```text
O(n) + O(log n)
= O(n + log n)
= O(n)
```

This is because `n` grows faster than `log n`.

### Case 2: Nested Operations

If an `O(log n)` operation is performed for each of `n` elements:

```text
n × O(log n)
= O(n log n)
```

For example, inserting `n` elements into a min-heap takes `O(n log n)` when analyzed as repeated insertions.

### Case 3: Sorting Plus Heap Processing

In our solution:

```text
Sorting       = O(n log n)
Heap          = O(n log n)
Total         = O(2n log n)
              = O(n log n)
```

We ignore constant factors in Big-O notation.

## 9. Interview-Ready Explanation

If the interviewer asks you to explain your solution, you can say:

"I was given a list of meeting intervals and a minimum gap that must be maintained between meetings scheduled in the same room. My goal was to find the minimum number of rooms required.

I first considered a brute-force approach in which I check every existing room for each meeting. This takes `O(n²)` time in the worst case because I may need to examine many rooms for every meeting.

To optimize it, I used a min-heap. I sort the meetings by start time and store each room's earliest reusable time, which is the previous meeting's end time plus the required gap.

For each meeting, I remove available room entries from the heap and insert the current meeting's end time plus the gap. The heap helps me efficiently identify rooms that can be reused.

The overall time complexity is `O(n log n)`, and the space complexity is `O(n)`. If the meetings are already sorted, I can skip the sorting step, although the worst-case time complexity remains `O(n log n)` because of the heap operations."
